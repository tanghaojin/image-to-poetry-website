# 前端统一图片配诗闭环

日期：2026-09-13

## 当前实现

- `useImagePoetry` 以 `multipart/form-data` 调用 `POST /api/v1/poetry/match`
- 同一次请求由后端完成图片预处理、模型理解和真实诗词匹配
- 请求携带 `X-Device-Fingerprint`，用于服务端 Redis 每日配额
- 模型密钥只保存在后端环境变量，前端公开运行配置仅包含 API 地址
- 匹配失败时重试同一个完整请求，不保留旧请求的中间状态
- 切换图片或卸载组件时取消当前请求，避免旧结果覆盖新图片
- 编辑器中的精选句、篇名、作者、朝代、全诗和匹配理由均来自接口
- Canvas 生成的海报文字、署名和下载文件名均来自接口
- 已删除旧的前端直连模型与单独诗词匹配 composable

## 已确认的真实模型验证

- 示例图片：`寒江孤舟`
- 服务端首选 `gemini-3.7-flash` 返回繁忙后，按顺序回退到 `gemini-3.6-flash` 并成功理解图片
- 返回主体包括划船者、小船、晨雾湖面和霜雪树木；判断为冬季、清晨、雾，可信度 95%
- 提示词返回项目词表中置信度最高的 1～3 个意境，匹配器按各意境置信度参与评分并兼容复合主体描述

完整浏览器端到端验证需 PostgreSQL、Redis 与 API 同时就绪后执行。
